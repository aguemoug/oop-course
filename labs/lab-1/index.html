Exercise 2: Moving to C++

Section titled “Exercise 2: Moving to C++”

Exercise 1 showed the limits of procedural programming. Before addressing them, we first migrate the program to C++ and use a few features that make C code cleaner and safer. Copy your validated program from Exercise 1 (without the lines added in Part 3) into a new exo2.cpp and compile it.

Part 1: Constants and Types

Section titled “Part 1: Constants and Types”
  • In C++, a struct name is already a type name. Rewrite the declaration of Student without typedef.

Part 2: References and const

Section titled “Part 2: References and const”
  • Make init_student() take a reference (Student &s) instead of a pointer. Update the body (s.age instead of s->age) and the calls (no more &). Why don’t the calls need & anymore? Name two differences between a reference and a pointer.
  • Make print_student() take a const Student &s. Add s.age = 0; to its body and compile. What happens, and when is the error detected?
  • Which functions of the program should take const parameters, and which should not? Justify your answer.

Part 3: Overloading and Default Arguments

Section titled “Part 3: Overloading and Default Arguments”
  • Rename both print_student() and print_all() to print(). Why does the program still compile? How does the compiler choose which function to call?
  • Give init_student() default values for the age and the grade (int age = 18, float grade = 0), then call init_student(students[2], "Amira", 17); and init_student(students[3], "Ahlem");. Why must default arguments come last in the parameter list?

Then try students[1].age = -3; in main(). What happens, and why can the validation no longer be bypassed?
