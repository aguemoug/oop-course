Lab 2: Classes and Encapsulation

Lab 2 : Classes and encapsulation

Section titled “Lab 2 : Classes and encapsulation”

Course: Object-Oriented Programming
Related lecture: Lecture 3 (defining classes and encapsulation)

Objectives

Section titled “Objectives”

By the end of this lab you will be able to:

  • explain the limits of the procedural approach (data and operations separated, no protection, no initialization guarantee);
  • define a C++ class with attributes and methods;
  • use public and private to restrict access to the state of an object;
  • identify and protect the invariants of a class.

Instructions

Section titled “Instructions”
  • Difficulty: ★ warm-up, ★★ standard.
  • For “find the error” and “predict the output” questions, answer on paper first, then compile and check.
  • Compile with g++ -std=c++17 -Wall -Wextra file.cpp -o prog and read the warnings.
  • The test programs below use std::cout: add #include <iostream> at the top of your file.

Exercise 6 ★★ : A queue

Section titled “Exercise 6 ★★ : A queue”

A queue stores its elements in FIFO order (First In, First Out). We implement it with a circular array.

Write a class Queue with:

  • Attributes (private): int mem[CAPACITY], int head (index of the first element) and int count (number of elements). Use #define CAPACITY 5.
  • Methods: isEmpty(), isFull(), size(), void enqueue(int) and int dequeue().
  • enqueue on a full queue and dequeue on an empty queue do nothing (dequeue returns 0 in that case, as in Stack).
  • The element after the last one is stored at index (head + count) % CAPACITY.

Questions:

  1. Write the invariants of Queue.
  2. Why would it be dangerous to make head and count public?
  3. Test with this main. Expected output: 5, 1 2, 5, 3 4 5 7 8.

Exercise 7 ★★ : Design discussion

Section titled “Exercise 7 ★★ : Design discussion”

In Lecture 3, Stack::pop() returns 0 when the stack is empty, and push silently does nothing when the stack is full.

  1. Why is returning 0 from pop() a bad design?
  2. Propose two different ways to redesign pop so that the caller can tell whether it succeeded. Write the signature of each (the code of the body is not required).
  3. Does your proposal respect encapsulation? Does it protect the invariant 0 <= top <= CAPACITY?
