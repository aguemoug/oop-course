Problems in the procedural implementation of the stack

Section titled “Problems in the procedural implementation of the stack”
  • Data and operations are separated: the stack and the operations that work on it are independent, so we must pass the stack as an argument on every call.
  • No data protection: the data can be changed in an uncontrolled way. For example, a programmer can directly modify the top index or the stored values.
  • No initialization guarantee: the data can be used in an uninitialized state, for example if the programmer forgets to call init().

Stack as a class

Section titled “Stack as a class”

A class groups data together with the operations that work on that data. The data members are called attributes, and the functions that belong to a class are called member functions or methods.

A stack can be seen as an object that has a state and a behavior:

  • State: elements, size, capacity
  • Behavior: push, pop, isEmpty, isFull

Encapsulation

Section titled “Encapsulation”

To avoid this problem, we introduce a key concept of object-oriented programming: encapsulation.

Encapsulation is the process of bundling an object’s data and the methods that operate on that data into a single unit (a class), while restricting direct access to the internal state and implementation.

Encapsulation acts as a protective barrier around data and logic. It hides internal implementation details and prevents outside code from modifying the state in unexpected ways.

To implement encapsulation, many programming languages provide access modifiers such as public and private.

In C++:

  • Members (attributes or methods) declared after public: are accessible from outside the class.
  • Members declared after private: are accessible only from within the class. Any attempt to access a private member from outside the class causes a compilation error.

Note

In a C++ class, members are private by default. In a struct, they are public by default.

In our example, the state of the stack is represented by the attributes mem and top, so we must prevent any external access to them.

The internal state of the stack can now only be updated by the class itself, through its own methods.

Tip

An object’s state should only be changed through its behavior. Every change of state must be justified by one of the object’s methods.

Caution

Encapsulation does not simply mean “attributes are private and methods are public”.

So what is encapsulation?

  • Bundling data and operations together
  • Hiding the internal state
  • Controlling access to the internal state through public methods
  • Protecting the object’s invariants

Invariant

An invariant is a condition that must always hold for a valid object. For the stack: 0 <= top <= CAPACITY.

Encapsulation idea Where it appears in the code
Bundle data + behavior mem[] and top live inside Stack, together with push/pop/size.
Hide internal state mem and top are private: main() cannot write s1.top = -5; or s1.mem[0] = 99;.
Controlled access via public methods The only way to change the stack is push() / pop().
Invariants protected Because outsiders cannot touch top, it can never be negative or greater than CAPACITY. pop() on empty and push() on full are handled inside the class.
