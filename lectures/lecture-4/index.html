Object initialization

Section titled “Object initialization”

If we declare a variable

what value should we expect in x? It is an uninitialized variable, and it is always advisable to give variables an initial value so that they are in a defined state.

What about our objects?

  • What is the state of the object s?
    • What is the value of the attribute top?
    • What values are stored in the array mem?

In our procedural version of the stack, we defined a function init to initialize the stack. However, we said that the programmer can forget to call init and use an uninitialized stack.

In object-oriented programming, we always want our objects to be in a valid state. A constructor is a special member function that is called automatically when an object is created. Its purpose is to initialize the object. A constructor has the same name as its class and has no return type.

[!warning] Warning A constructor has no return type, not even void.

[!note] Note If we do not define any constructor, the compiler generates an empty one for us (it does nothing, so top and mem would stay uninitialized). As soon as we define our own constructor, the compiler stops generating it.

In C++, constructors can use member initializer lists. In the following example, the attribute top is initialized to 0 before the body of the constructor runs.

An initializer list initializes each member directly, instead of creating it first and assigning to it later. It is the preferred way to initialize attributes in C++, and it is the only way to initialize members that cannot be assigned (such as const members and references).

Constructors with parameters

Section titled “Constructors with parameters”

[!abstract] Our Stack class uses a static capacity defined by the constant CAPACITY: all Stack objects have the same fixed capacity. What if we want to create stacks with a custom capacity?

To implement a variable capacity stack we need to change our Stack class design.

  • The capacity now becomes part of the stack’s state and is defined when the stack is created.
  • An array has a fixed size known at compile time, so mem must now be allocated dynamically, based on the capacity of the stack.
  • The method size() is renamed getSize(), and we add the getter getCapacity().

Setting the capacity and allocating the memory must be done when the object is created, so this is the job of the constructor.

How do we tell the constructor the desired capacity? Like methods, constructors accept arguments, so we add a parameter that sets the capacity of the stack.

[!note] Note malloc is declared in <cstdlib>. The members are initialized in the order in which they are declared in the class (mem, top, capacity), not in the order of the initializer list, so we always write the list in the same order.

[!note] Note In capacity(capacity), the name outside the parentheses is the attribute and the name inside is the parameter. Inside the constructor body, capacity refers to the parameter (it hides the attribute, but both have the same value here).

[!note] Note A constructor is not only used to initialize attributes. It can also acquire resources for the object, such as memory.

[!note] Note Since Stack now has a constructor that requires an argument, the declaration Stack s; no longer compiles: every stack must be created with a capacity. Later in this lecture we will see how to also allow Stack s; using a default argument.

[!tip] Exercise A stack must satisfy the invariant capacity > 0. What happens if we write Stack s(0); or Stack s(-5);? How could the constructor protect this invariant?

Destructors

Section titled “Destructors”

We saw that an object can acquire resources when it is initialized. How do we ensure that the object gives those resources back when it is finished with them?

In our last version of Stack, the constructor allocates dynamic memory. How does the object release that memory?

  • We cannot call free on mem from outside, because it is part of the state and it is private.
  • We cannot make the pointer public, since that would violate the encapsulation principle.
  • We could add a release() method to the class, but the programmer may forget to call it, or call it too early and keep using the object after the memory was freed.

In C++, we define a special method called a destructor. It is called automatically when the object is about to be destroyed. We use it to release the resources acquired in the constructor.

A destructor has the same name as the class, preceded by ~. It has no parameters and no return type, so a class can have only one destructor.

Function overloading

Section titled “Function overloading”

In C++, we can define multiple functions that share the same name, as long as they differ in the number or the types of their parameters. This is called function overloading.

[!warning] Warning Look at the line return max(max(a, b), c); in the second definition. It is not recursion: max is not calling itself, it is calling the other overload (the one with two parameters).

Rules for function overloading

Section titled “Rules for function overloading”
  • Overloaded functions must differ in the number of parameters, their types, or their order.
  • The return type is not part of the distinction. Two functions that differ only in their return type cannot be overloaded.
  • Parameter names do not matter.
  • The compiler chooses the overload at compile time, by comparing the arguments of the call with the parameters of each candidate. The best match wins: an exact match is preferred over a match that needs a conversion.
  • If no overload matches, or if several overloads match equally well, the call is an error (the second case is called an ambiguous call).

Default arguments

Section titled “Default arguments”

In C++, functions can define default values for their parameters. The default value is used when the argument is omitted in the function call.

Rules for default arguments

Section titled “Rules for default arguments”
  • Default values are given from the right: once a parameter has a default value, all the parameters to its right must also have one.
  • When calling, arguments are omitted from the right as well. We cannot skip an argument in the middle.
  • A default value is written once, in the function declaration (not repeated in a separate definition).

Overloading and default arguments conflicts

Section titled “Overloading and default arguments conflicts”

Default arguments and overloading can be combined, but a default argument is like a hidden overload: push(int value, int times = 1) can be called with one or two arguments. If another overload accepts the same call, the compiler cannot choose and reports an ambiguous call.

Dynamic object creation

Section titled “Dynamic object creation”

In C++ we can create pointers to objects like we create pointers to other data types:

Notice that we use the arrow operator -> to call a method through a pointer. sp->push(20) is a shorthand for (*sp).push(20).

[!warning] Warning Be careful when using pointers to objects, because they can be null. Calling a method through a null pointer is an error.

We can also create an object dynamically using the new keyword:

If the constructor has a default argument, we can omit the argument: new Stack creates a stack of capacity 100.

Objects created with new have a different lifetime from local objects:

  • A local object (Stack s(20);) is created at its declaration and destroyed automatically at the end of its block.
  • A dynamic object (new Stack(20)) lives until we explicitly destroy it with delete, even after the function that created it has returned.

[!warning] Warning When we create objects dynamically using the new keyword, we need to delete them manually when we are finished with them. If we forget the delete, the destructor is never called, so the object’s memory and the memory allocated inside it (mem) are never released: this is a memory leak. Also, never delete the same pointer twice. Setting the pointer to nullptr after delete is a good habit, since deleting a null pointer is safe and does nothing.

References

Section titled “References”

In C++, a reference is an alias (an alternative name) for an existing variable.

[!note] Note The symbol & has two different meanings. In an expression (&a) it is the address-of operator. In a declaration (int &r) it means “reference”.

Unlike pointers, references cannot be null: a reference must always refer to an existing variable or object, so it must be initialized when it is declared.

References are mostly used to pass objects to functions without copying them:

Summary

Section titled “Summary”
  • A constructor initializes the object when it is created: same name as the class, no return type, can have parameters.
  • A destructor (~ClassName) releases the resources of the object when it is destroyed: no parameters, no return type, only one per class.
  • Overloading lets several functions, methods or constructors share a name if their parameters differ. Default arguments let us omit trailing arguments.
  • Combining overloading and default arguments can produce ambiguous calls.
  • new / delete replace malloc / free in C++, and unlike them they call the constructor and the destructor. Use delete[] for new[].
  • Objects can be created dynamically with new and must be destroyed with delete.
  • A reference is an alias for an existing variable: it cannot be null and cannot be rebound.
